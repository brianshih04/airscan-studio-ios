### Fix 3 — generation token(原 #3,P1)✅ 解決,帶 1 寋 P2 尾巴

驗證狀態機:
- `startScan`:scanTask==nil 才啟動、generation+1 並捕獲、Task 收尾 `self?.scanTask = nil`(147-152)。

推演競態窗口:
1. cancel → start:cancel 時 gen+1 → 新 Task gen=2;舊 Task 收尾 gen(1)≠2,不寫 phase。✅ 不會蓋掉新掃描。
2. start → cancel(舊還在跑):cancel gen+1,舊 Task gen≠current → 不寫。✅
3. cancel → cancel → start:同 1。✅
4. **startScan 重入**:scanTask != nil 時 guard return,不會 gen+1,✅。
5. **cancel 後 scanTask 尚未清 nil 的窗口**:cancel 只 cancel() 不清 nil → startScan guard 擋住 → 使用者按「取消」後到舊 Task 真正收尾前,「開始掃描」按鈕若綁 isScanning(scanTask != nil)則暫時不可按。舊 Task 收尾清 nil 後恢復。這是設計取捨(防雙掃描),行為正確,無資料錯誤。**副作用**:cancel 與 scanTask=nil 之間 isScanning=true 但 phase=.idle,UI 若以 isScanning 決定按鈕,取消後短暫「卡在掃描中」外觀;取消失立即生效。小 UX 瑕疵,P2。
